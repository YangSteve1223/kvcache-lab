# 实验日志：任务类型对压缩敏感性的差异

- 日期：2024-01-15
- 假设：不同任务类型（数学推理/代码生成/对话QA）对KV压缩的敏感度不同

## 方法

**任务材料**：
- 数学推理（math）：3个样本，涉及公式计算和方程求解
- 代码生成（code）：3个样本，涉及Python/JS代码和Git操作
- 对话QA（qa）：3个样本，涉及需求理解和报告生成

**压缩配置**：
- 无压缩（none）：完整context
- 中间压缩（middle）：删除context中间部分
- 头部压缩（head）：删除context开头部分

**测量指标**：质量评分（0-10）、TTFT（ms）

## 结果

| 任务类型 | 压缩方式 | 平均质量 | 平均TTFT(ms) |
|----------|----------|----------|--------------|
| math | none | 9.00 | 4334 |
| math | middle | 8.67 | 3537 |
| math | head | 8.67 | 3644 |
| code | none | 6.00 | 3288 |
| code | middle | 6.33 | 3745 |
| code | head | 6.00 | 2883 |
| qa | none | 8.00 | 6499 |
| qa | middle | 8.00 | 5490 |
| qa | head | 7.67 | 6328 |

## 压缩敏感度分析

| 任务类型 | 中间压缩损失 | 头部压缩损失 |
|----------|-------------|-------------|
| math | 3.7% | 3.7% |
| code | -5.6% | 0.0% |
| qa | 0.0% | 4.2% |

## 结论

**假设成立**：
1. **数学推理任务**对压缩最敏感（3.7%损失），需要完整的公式和推导步骤
2. **代码任务**对压缩鲁棒性较好，中间压缩反而有轻微提升（可能是噪声或模型能力差异）
3. **QA任务**对头部压缩更敏感（4.2%损失），因为关键信息通常在开头部分

## 关键发现

1. 不同任务类型对压缩位置的敏感度确实存在差异
2. 头部压缩对QA任务影响更大，可能是因为对话背景和系统指令通常在开头
3. 数学任务对中间压缩和头部压缩同样敏感，表明中间步骤也很重要
4. 代码生成任务质量整体较低（5-6分），可能是任务复杂度较高
