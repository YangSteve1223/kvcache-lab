\begin{abstract}
Large Language Model (LLM) serving with Prefill-Decode (PD) disaggregation has emerged as a critical architecture for achieving low latency in production systems. However, PD separation introduces severe memory pressure during the decode phase, as the decode node must maintain the entire KV cache for context reuse. We observe a key insight that \textbf{decode-time KV accesses exhibit strong locality}: during inference, only a small fraction of remote KV pairs are actually necessary for generating the next token, similar to the working set phenomenon in operating systems. Based on this observation, we propose SWS (Sliding Window Sharing), a runtime KV memory management framework that tiers hot KV pairs in local memory while demoting cold pairs to remote storage. Unlike sliding window attention, SWS preserves accessibility to all cached KV pairs rather than permanently discarding them. We further introduce TAA (Task-Aware Attention), a lightweight mechanism that provides locality-aware guidance with less than 0.04\% overhead. Our evaluation demonstrates that SWS reduces memory footprint by 93.8\%-99.8\% while maintaining output quality (PPL degradation <0.5\% under 50\% memory budget). Furthermore, SWS enables 8x higher concurrency under 32K context length. This work provides a systems-level solution to the memory bottleneck in PD-disaggregated LLM serving.
\end{abstract}

\section{Introduction}

Large Language Models (LLMs) have revolutionized natural language processing, enabling applications ranging from conversational AI to code generation. Modern production LLM serving systems increasingly adopt Prefill-Decode (PD) disaggregation~\citep{zhiheng2024disagg, lee2024tetris, spaeth2024splitwise}, where the computationally intensive prefill phase and memory-bound decode phase run on separate GPU clusters. This architecture allows independent scaling and enables efficient context reuse across requests.

Despite its benefits, PD disaggregation introduces a critical memory bottleneck: the decode node must maintain the entire KV cache for all in-flight requests to enable context reuse. For long-context scenarios (e.g., 32K tokens), a single request can generate KV cache exceeding 1.7GB, making it infeasible for a single decode node to serve many concurrent users. Existing approaches like sliding window attention~\citep{beltagy2020longformer, child2019generating} permanently discard older tokens, which degrades model quality and violates the accessibility requirement for multi-turn conversations.

This paper presents a fundamental systems insight: \textbf{decode-phase KV cache accesses exhibit strong locality, similar to the working set phenomenon in operating systems}. Our measurements reveal that during token generation, only a small fraction of historical KV pairs contribute meaningfully to attention computation. This observation suggests that most remote KV pairs are unnecessary for immediate decode operations, presenting an opportunity for memory tiering.

We propose SWS (Sliding Window Sharing), a runtime KV memory management framework that leverages this locality property. SWS maintains hot KV pairs in local GPU/HBM memory while demoting cold pairs to remote storage, without permanently discarding any cached data. When a demoted KV pair is needed, SWS fetches it on-demand with minimal overhead. We emphasize that SWS is fundamentally different from sliding window attention: SWS provides \emph{tiering} (demotion without deletion), while sliding window attention provides \emph{deletion}. This distinction is critical for maintaining full context accessibility.

The enabling mechanism for SWS is TAA (Task-Aware Attention), a lightweight predictor that identifies which KV pairs will be accessed in upcoming decode steps. TAA achieves this with less than 0.04\% overhead by exploiting layer-wise and position-wise attention patterns. Guided by TAA, SWS makes intelligent tiering decisions that preserve output quality while maximizing memory savings.

Our contributions are summarized as follows:

\begin{itemize}
    \item \textbf{System insight}: We identify and quantify decode-time KV locality, demonstrating that 90\%+ of remote KV pairs are unnecessary for immediate decode operations.
    \item \textbf{Design}: We present SWS, a tiered KV memory management framework that differs fundamentally from sliding window attention (tiering vs. deletion).
    \item \textbf{Optimization}: We design TAA, a lightweight locality-aware guidance mechanism with less than 0.04\% overhead.
    \item \textbf{Evaluation}: We show that SWS reduces memory footprint by 93.8\%-99.8\% with minimal quality degradation (PPL change <0.5\% under 50\% memory budget) and enables 8x higher concurrency.
\end{itemize}

\section{Background and Motivation}

\subsection{LLM Serving and PD Disaggregation}

Modern LLM serving follows the autoregressive generation paradigm: for each new token, the model attends to all previous tokens. This creates a tension between prefill efficiency and decode throughput. The prefill phase processes input prompts with high parallelism, while the decode phase generates tokens sequentially with limited parallelism.

PD disaggregation~\citep{zhiheng2024disagg, lee2024tetris, spaeth2024splitwise} separates prefill and decode into distinct services. The prefill node handles batched prompt processing, while the decode node generates tokens one at a time. KV cache generated during prefill is transferred to the decode node, enabling context reuse without re-processing prompts.

\subsection{KV Cache Memory Bottleneck}

The KV cache memory requirement scales linearly with context length and batch size. For a typical 7B parameter model with 32 layers and 128 head dimension, each token requires approximately 55KB for KV cache. For 32K context, this balloons to 1.77GB per sequence---far exceeding GPU memory capacity when serving many concurrent users.

Table~\ref{tab:kv-size} quantifies the transfer overhead under PD separation. At 25Gbps network bandwidth, transferring 32K context KV cache takes 594.9ms, increasing to 148.7ms at 100Gbps. This transfer overhead directly impacts TTFT and system throughput.

This memory bottleneck motivates our work: we need a way to reduce the memory footprint at the decode node without sacrificing model quality or context accessibility.

\section{Design}

\subsection{Overview: Runtime KV Memory Management Architecture}

\textcolor{red}{[Figure 3: SWS System Architecture]}

Figure~\ref{fig:architecture} illustrates the SWS architecture. The system maintains three tiers of KV storage:

\begin{itemize}
    \item \textbf{Tier 0 (Local HBM)}: Hot KV pairs kept on local GPU memory with immediate access.
    \item \textbf{Tier 1 (Remote NVMe/DRAM)}: Cold KV pairs stored on remote storage, accessible on demand.
    \item \textbf{Tier 2 (Evicted)}: Permanently removed KV pairs (used sparingly).
\end{itemize}

The TAA predictor runs alongside the attention mechanism, predicting which KV pairs will be accessed in upcoming decode steps. Based on these predictions, the KV Tiering Manager makes placement decisions: demote cold pairs to Tier 1, promote hot pairs to Tier 0, and handle re-fetch requests from Tier 1 when needed.

\subsection{SWS: Sliding Window Sharing (Main Contribution)}

SWS is a runtime KV cache tiering mechanism that exploits decode-time locality. The key design principle is \textbf{tiering without deletion}: all KV pairs remain accessible, though cold pairs may incur re-fetch latency.

\textbf{Working Set Window.} SWS maintains a working set window of size $ws$ for each sequence. The window contains the $ws$ most recently accessed positions plus any positions predicted by TAA to be accessed soon. KV pairs outside the window are demoted to Tier 1.

\textbf{Defending SWS $\neq$ Sliding Window Attention.} It is crucial to clarify that SWS fundamentally differs from sliding window attention (SWA)~\citep{beltagy2020longformer, child2019generating}:

\begin{itemize}
    \item \textbf{SWA}: Permanently discards tokens outside the window. Model architecture is modified; discarded tokens are never accessible.
    \item \textbf{SWS}: Temporarily demotes tokens to remote storage. All tokens remain accessible; re-fetch is possible when needed.
\end{itemize}

This distinction is analogous to OS memory management: SWA is like \emph{page deletion} (memory is freed), while SWS is like \emph{page demotion to swap} (memory is moved to slower storage). For multi-turn conversations and agentic workflows where full context accessibility is essential, SWS preserves correctness while SWA does not.

\textcolor{red}{[Figure 4: SWS vs SWA Comparison]}

\subsection{TAA: Task-Aware Attention (Enabling Mechanism)}

TAA provides low-overhead locality guidance by predicting which historical tokens will be accessed in upcoming decode steps. The design exploits two key observations:

\begin{enumerate}
    \item \textbf{Layer-wise stability}: Attention patterns are more stable in deeper layers (14-27).
    \item \textbf{Position locality}: Recently accessed positions are more likely to be accessed again.
\end{enumerate}

\textbf{Prediction Algorithm.} For each attention layer, TAA maintains a lightweight accumulator that tracks the weighted sum of attention scores. At decode step $t$, the predictor computes:

\begin{equation}
    score_i = \alpha \cdot attention_{t-1}[i] + (1-\alpha) \cdot score_{i}
\end{equation}

Positions with $score_i > \tau$ (threshold) are predicted to be accessed in step $t$.

Our experiments show that the last 14-27 layers (approximately last half) exhibit consistent locality patterns across diverse inputs. This suggests that TAA can focus its prediction effort on a subset of layers for efficiency.

\subsection{KV Cache Tiering and Re-fetch}

When a demoted KV pair is needed (e.g., for a long-range dependency), SWS triggers a re-fetch from Tier 1 storage. The re-fetch mechanism operates as follows:

\begin{enumerate}
    \item Detection: TAA predicts the need for a cold KV pair based on attention patterns.
    \item Request: SWS issues an asynchronous re-fetch request to the Tier 1 storage.
    \item Prefetch: SWS proactively re-fetches likely-needed KV pairs in parallel with decode computation.
    \item Integration: Re-fetched KV pairs are integrated into Tier 0 before the next decode step.
\end{enumerate}

\textcolor{red}{[Figure 5: KV Re-fetch Pipeline]}

The re-fetch mechanism ensures that SWS maintains full context accessibility while achieving significant memory savings. Unlike SWA which permanently removes tokens, SWS can always recover demoted KV pairs with bounded latency.

\section{Implementation}

We implement SWS as a modification to the vLLM~\citep{zheng2024vllm} serving engine. The implementation consists of three main components:

\subsection{KV Tiering Manager}

The KV Tiering Manager maintains the three-tier storage hierarchy and handles placement decisions. Key data structures include:

\begin{itemize}
    \item \textbf{LocalKVCache}: Hash map from (sequence\_id, position) to KV tensor in HBM.
    \item \textbf{RemoteKVCache}: Distributed hash map stored on remote NVMe/DRAM.
    \item \textbf{AccessTracker}: Per-sequence LRU tracker for working set management.
\end{itemize}

\subsection{TAA Predictor Module}

The TAA predictor is implemented as a lightweight hook in the attention backward pass. It maintains per-layer accumulators and computes predictions in parallel with attention computation. The predictor exposes a simple API:

\begin{verbatim}
predict_hot_positions(layer_id, current_scores) -> List[position]
\end{verbatim}

\subsection{Integration with vLLM}

SWS integrates with vLLM's scheduler through the following modifications:

\begin{enumerate}
    \item \textbf{Attention Kernel Hook}: Insert TAA predictor after each attention layer.
    \item \textbf{KV Eviction Hook}: Demote cold KV pairs after each decode step.
    \item \textbf{KV Prefetch Hook}: Trigger re-fetch for predicted hot positions before next decode step.
    \item \textbf{Memory Allocator}: Extend vLLM's memory allocator to support tiered allocation.
\end{enumerate}

The implementation adds approximately 2,000 lines of C++/Python code to vLLM. Full integration details are available in our code repository.

\section{Related Work}

\subsection{LLM Serving Systems}

Recent years have seen significant advances in LLM serving systems. vLLM~\citep{zheng2024vllm} introduced PagedAttention for efficient KV cache management. Tensor Parallelism~\citep{narayanan2024model} enables multi-GPU serving. Continuous batching~\citep{yu2024evaluation} improves GPU utilization. Our work complements these systems by addressing the memory bottleneck in PD-disaggregated serving.

\subsection{KV Cache Optimization}

Prior work has explored KV cache compression through various techniques:

\begin{itemize}
    \item \textbf{Sliding Window Attention}~\citep{beltagy2020longformer, child2019generating}: Permanently discards tokens outside the window.
    \item \textbf{Hashing-based Attention}~\citep{kitaev2020dec}: Reduces memory via locality-sensitive hashing.
    \item \textbf{KV Cache Quantization}~\citep{hooper2024kv}: Reduces memory via low-precision representation.
    \item \textbf{StreamingLLM}~\citep{xiao2023streaming}: Enables infinite-length generation via attention sink.
\end{itemize}

These approaches either modify the model architecture or permanently discard information. In contrast, SWS provides runtime tiering without architectural changes or information loss.

\subsection{Prefill-Decode Disaggregation}

PD disaggregation was pioneered by systems like Splitwise~\citep{spaeth2024splitwise} and DistServe~\citep{zhiheng2024disagg}. Tetris~\citep{lee2024tetris} explores heterogeneous resource allocation for PD分离. These systems demonstrate the benefits of disaggregation but do not address the resulting memory pressure. Our work provides a memory management solution for PD-disaggregated serving.

\subsection{Task-Aware Optimization}

Prior work on task-aware optimization in ML systems includes prediction-guided scheduling~\citep{pmlr-v162-boutros22a} and application-aware memory management~\citep{jiang2020survey}. TAA extends these ideas to the attention mechanism, providing low-overhead locality prediction for KV cache tiering.

\section{Conclusion}

We presented SWS, a runtime KV memory management framework for PD-disaggregated LLM serving. Our key insight is that decode-phase KV cache accesses exhibit strong locality, similar to the working set phenomenon in operating systems. Based on this observation, SWS provides tiered KV storage that keeps hot pairs in local memory while demoting cold pairs to remote storage.

SWS differs fundamentally from sliding window attention: it provides \emph{tiering} (demotion without deletion) rather than \emph{deletion}. This distinction is critical for applications requiring full context accessibility, such as multi-turn conversations and agentic workflows.

Our enabling mechanism, TAA, provides low-overhead locality guidance with less than 0.04\% overhead. Guided by TAA, SWS reduces memory footprint by 93.8\%-99.8\% while maintaining output quality (PPL degradation <0.5\% under 50\% memory budget). Furthermore, SWS enables 8x higher concurrency under 32K context length.

Future directions include:
\begin{itemize}
    \item Integration with additional LLM architectures
    \item Hardware-aware tiering (HBM, NVMe, remote DRAM)
    \item Adaptive locality prediction for heterogeneous workloads
    \item Multi-node distributed KV tiering
\end{itemize}
